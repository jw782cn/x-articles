# [2026-04-08] Amazon S3 Files：让 S3 桶可作为文件系统直接访问

原文链接：Announcing Amazon S3 Files, making S3 buckets accessible as file systems by AWS

S3 Files 提供了一个共享文件系统，可以将任何 AWS 计算资源直接连接到 Amazon S3 中的数据。有了 S3 Files，Amazon S3 成为第一个也是唯一一个能为数据提供功能完备、高性能文件系统访问的云对象存储。它提供完整的文件系统语义和低延迟性能，而数据始终不会离开 S3。

这意味着基于文件的应用、AI Agent 和团队现在可以使用他们已有的工具，像访问文件系统一样访问和处理 S3 中的数据。S3 Files 基于 Amazon EFS 构建，兼具文件系统的性能和简洁性，以及 S3 的可扩展性、持久性和成本效益。

你不再需要复制数据或在对象存储和文件系统存储之间来回搬运。S3 Files 维护桶中对象的视图，并智能地将文件系统操作转换为高效的 S3 请求。你的文件应用无需修改代码即可运行在 S3 数据上，AI Agent 可以跨流水线持久化记忆和共享状态，ML 团队可以直接运行数据准备工作负载，无需先复制或暂存文件。

## 解决了什么问题

企业将分析数据和数据湖存储在 S3 中，但基于文件的工具、Agent 和应用一直无法直接访问这些数据。要弥合这个差距，就得管理一个独立的文件系统、复制数据，并构建复杂的同步管道。S3 Files 消除了这些摩擦和开销。

使用 S3 Files，你的数据可以同时通过文件系统和 S3 API 直接访问。数千个计算资源可以同时连接到同一个 S3 文件系统，实现跨集群的共享访问而无需复制数据。S3 Files 适用于 S3 桶中所有新旧数据，无需迁移。

## 性能

S3 Files 缓存活跃使用的数据以实现低延迟访问，并提供高达每秒数 TB 的聚合读取吞吐量，存储永远不会成为性能瓶颈。没有数据孤岛，没有同步复杂性，没有取舍。文件存储和对象存储，在一个地方统一，毫不妥协。

## 可用性

S3 Files 现已在 34 个 AWS 区域正式可用（GA）。

核心观点：AWS 让 S3 桶可以直接作为文件系统挂载访问，解决了对象存储和文件存储之间的老大难问题。AI Agent、ML 团队和文件应用可以直接读写 S3 数据，不用再复制数据或维护同步管道。基于 EFS 构建，性能和兼容性都有保障。
