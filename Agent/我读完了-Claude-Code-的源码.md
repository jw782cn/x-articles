这是让我震惊的地方。

再读一遍。

5 个 agent。和 1 个一样的成本。因为它们都命中了 prompt cache。

大多数人把 Claude Code 当作单个 worker 来用。一次一个任务。等它完成。给它下一个。

## 8. 流式架构意味着中断代价很低

整个管道使用 async generator 逐个事件 yield。按 Escape 键可以干净地中止当前流，而不会丢失之前的上下文。

这看起来是小事，但它改变了你应该如何使用 Claude Code。

不要等待一个你知道正在出错的回复。立即中断并重新引导。源码就是为此设计的。你之前的上下文被保留。被中断的回复被干净地丢弃。零惩罚。

把它想象成结对编程。如果你的搭档开始走上错误的方向，你不会等他们说完。你会说"实际上，走这条路。"同样的思路。

核心观点：Claude Code 不是一个简单的终端聊天工具，而是一个完整的 agent 编排平台。真正高效使用它的关键在于三件事：用 CLAUDE.md 持久化你的项目知识（每轮加载），用子 agent 并行化任务（共享 prompt cache 几乎免费），以及用 hook 系统将它嵌入你的开发工作流。配置胜过 prompting。
