## 引言

LongMemEval 是目前公开可用的最严格的长期记忆基准测试之一。与那些只测试短上下文简单检索的基准不同，LongMemEval 模拟的是真实生产环境中的混乱场景：超过 115k token 的对话历史、相互矛盾的信息、分散在多个会话中的事件，以及需要对时间进行推理的问题。

大多数记忆系统得分不高，问题通常出在检索上——而不是推理。即使召回率很高，如果检索带来大量噪音，LLM 可能仍然难以有效利用。核心问题在于如何只把正确的信息放入上下文窗口，更难的是：如何判断一个检索到的事实已经过时，被更新的版本所取代。

为了解决这个问题，我们放弃了传统 RAG，构建了一个多 Agent 协同的流水线。

---

## 实验设置与架构

标准的向量搜索在一般场景下表现不错。然而，当面对密集的、多会话的时序数据时，它就力不从心了。语义相似度匹配无法可靠地区分旧事实和新的修正信息。为了应对 LongMemEval 的复杂性，我们不得不从头重新设计摄入和检索流水线，用主动的 Agent 推理取代向量运算。

就像 ASMR 一样，这项技术简单而令人满足。

### 1. 并行编排与数据摄入（Observer Agents）

我们没有对用户会话进行分块和向量化，而是部署了一个 Agent 编排器，使用 3 个并行的阅读（观察者）Agent（由 Gemini 2.0 Flash 驱动）。这些 Agent 并发地阅读原始会话（例如，Agent 1 处理第 1、3、5 个会话；Agent 2 处理第 2、4、6 个）。

它们的目标是围绕六个维度进行有针对性的知识提取：个人信息、偏好、事件、时序数据、更新和助手信息。这些结构化的发现随后被原生存储，并映射到其来源会话。

### 2. 主动 Agent 检索（Search Agents）

当问题到来时，我们不会查询向量数据库。取而代之的是，我们部署 3 个并行的搜索 Agent。这些 Agent 主动阅读并推理已存储的发现，每个都有专门的关注点：

编排器汇总所有三个搜索 Agent 的发现，并提取逐字的会话原文用于细节验证。这使得检索基于真正的认知理解，而非仅仅依赖关键词或数学相似度。

### 3. Agent 编排的回答集成

当上下文组装完成后，单一的 prompt 无法处理 LongMemEval 中各种各样的问题类型。有些问题需要你推断细节，而另一些则要求你精确到位。我们尝试了两种不同的 Agent 回答流程：

实验一：8 变体集成（98.60% 准确率）

在第一种方案中，我们将检索到的上下文通过 8 个高度专业化的 prompt 变体并行处理（例如，精确计数器、时间专家、上下文深度分析等）。每个变体独立评估上下文并生成答案。只要 8 条不同推理路径中的任何一条成功得出了正确答案，该问题就被标记为正确。这种并行多判断方案让我们达到了惊人的 98.60% 总体准确率，完美地覆盖了我们的盲区。

实验二：12 变体决策森林（97.20% 准确率）

为了测试一个能产生单一权威答案（而非依赖多次独立尝试）的系统，我们将架构扩展为 12 变体决策森林。

在这里，12 个高度专业化的 Agent（由 GPT-4o-mini 驱动）独立回答问题。然后，我们引入了一个 Aggregator LLM 作为最终裁判。Aggregator 通过多数投票、领域信任度和冲突消解来综合 12 个答案。这个单一共识模型同样达到了令人难以置信的 97.20% 准确率。
