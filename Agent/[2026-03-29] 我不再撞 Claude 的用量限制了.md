# [2026-03-29] 我不再撞 Claude 的用量限制了

**原文链接**：[I stopped hitting Claude's usage limits - 10 things I changed](https://x.com/0x_kaize/status/2038286026284667239) by **@0x_kaize****209万阅读** | **3098点赞** | **11938收藏**

大多数人都怪 Claude 限制太严格。我以前也怪 Claude。

但最近我意识到，Claude 并不是按消息条数计费的，而是按 token 计费。你只需要聪明地使用 token，但并不是所有人都知道怎么做，结果白白浪费了大量 token 和金钱。

我深入研究了这个问题，整理出了一份最佳习惯清单，能帮你省下大量 token。

## 1. 编辑你的 prompt，不要发后续消息

当 Claude 没有正确理解你的想法时，你可能会忍不住发：

1/ "不是，我的意思是 [你的消息]"2/ "唉，这不是我想要的 [你的消息]"诸如此类

别这么做！

每条后续消息都会被加入对话历史。Claude 每轮都会重新读取全部历史记录，把 token 浪费在那些根本没帮上忙的上下文上。

每条消息的 token 成本 = 所有之前的消息 + 你的新消息。

按每轮约 500 token 计算：

第 30 条消息的成本是第 1 条的 31 倍。

正确做法：点击你原始消息的「编辑」按钮，修改后重新生成。旧的对话会被替换，而不是叠加。

## 2. 每 15-20 条消息就开一个新对话

在上一节中，我展示了 token 成本如何随消息增长。

理想情况下，你应该每 15-20 条消息就开一个新对话。

想象一下一个 100 多条消息的对话。按每轮约 500 token 计算，那就是超过 250 万个 token 被烧掉了，其中大部分只是在重新读取旧的历史记录。

有个开发者追踪了自己的使用情况，发现 98.5% 的 token 都花在了重新读取历史上。只有 1.5% 真正用于输出结果。

当对话变长时，让 Claude 总结所有内容，复制总结，开新对话，把总结作为第一条消息粘贴进去。

## 3. 把问题打包成一条消息

很多人认为把问题拆成单独的消息会得到更好的结果。但几乎所有情况下，事实恰恰相反。

三个单独的 prompt = 三次上下文加载。一个包含三个任务的 prompt = 一次上下文加载。

你能省两次 token：更少的上下文重载，同时离触及用量上限更远。

不要这样："帮我总结这篇文章""现在列出要点""再建议一个标题"

要这样写："帮我总结这篇文章，列出要点，并建议一个标题。"

额外好处：答案往往更好，因为 Claude 一开始就能看到完整的全貌。

三个问题，一条 Prompt，永远如此！

## 4. 把常用文件上传到 Projects

如果你在多个对话中上传同一个 PDF，Claude 每次都会重新对文档进行 token 化处理。

改用 Projects 功能。

上传一次文件，它就会被缓存。该项目内的每个新对话都会引用它，而不会再次消耗 token。

反复访问缓存的项目内容不会计入你的用量。

如果你经常处理合同、简报、风格指南或任何长文档，仅这一项就能大幅削减你的 token 开支。

## 5. 设置 Memory 和用户偏好

每个没有保存上下文的新对话都会浪费 3-5 条消息在初始设置上："我是一个市场营销人员，我的写作风格偏轻松，我喜欢短段落……"

你可能见过很多人每次 prompt 都以"扮演一个..."开头，那就是在重复烧 token。Claude 可以永久记住这些信息。

去「设置」→「Memory 和用户设置」。把你的角色、沟通风格和偏好保存一次。Claude 会自动在每个新对话中应用这些设置。

## 6. 关掉你没在用的功能

网页搜索、连接器和「探索」模式，这些都会给每个回复增加额外的 token 消耗，即使你根本不需要它们。

在写你自己的内容？

关掉「搜索和工具」功能。

「高级思考」功能同样消耗 token。默认关闭它。只有在第一次尝试不满意时才打开。

规则：如果你不是有意打开某个功能，那就把它关掉。

## 7. 简单任务用 Haiku

语法检查、头脑风暴、格式化、快速翻译、简短回答，这些 Haiku 都能搞定，成本远低于 Sonnet 或 Opus。

选对模型是你每天做出的最重要的决定。

用 Haiku 处理草稿和简单任务，可以释放 50-70% 的预算给那些真正需要强模型的任务。

简单任务不需要强模型！

## 8. 把工作分散到一天中

Claude 系统使用滚动 5 小时窗口。它不会在午夜重置，你的限额是逐渐递减的。上午 9 点发送的消息到下午 2 点就不再计入了。

如果你在一个上午的工作中就用完了全部限额，你一天中大部分的额度其实都没用上。

把一天分成 2-3 个时段：上午、下午和晚上。当你回来时，之前的用量已经不再计入，你又有了新的额度。

## 9. 在非高峰时段工作

从 2026 年 3 月 26 日起，Anthropic 在高峰时段会更快地消耗你的 5 小时会话限额：

同样的查询、同样的对话，但在高峰时段对你限额的影响更大。

你的每周总限额不变。但分配方式变了。在晚上或周末运行资源密集型任务会显著延长你的套餐使用时间。

如果你在美国以外（欧洲、拉美或亚洲），高峰时段可能正好落在你的下午，所以请根据时区换算一下。

## 10. 开启 Extra Usage 作为安全网

Pro、Max 5x 和 Max 20x 计划的订阅用户可以在「设置」→「用量」中启用「超额」功能。

当你的会话限额用完时，Claude 不会阻断你的访问。它会切换到按 API 费率的按量计费。

你可以设置月度消费上限来避免意外账单。

这不是为了省 token，而是为了不在最糟糕的时刻丢掉你的工作成果。

## 结语

一开始要遵循所有这些规则会很难，但一旦你能自动化地应用它们，你几乎永远不会再撞到限额。

你甚至可能从 Max 套餐降级到普通套餐，因为你的 token 绰绰有余！

Claude 不计算消息数。它计算的是 token。

**核心观点**：Claude 的用量限制本质上是 token 限制而非消息限制。通过编辑而非追加消息、定期开新对话、批量提问、利用 Projects 缓存、设置 Memory、关闭多余功能、选对模型、分时段工作等 10 个习惯，可以大幅减少 token 浪费，甚至从高价套餐降级到普通套餐
